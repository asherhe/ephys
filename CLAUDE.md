# CLAUDE.md

ephys: a 2D rigidbody physics engine in C++ (modeled on cyclone physics), compiled to WebAssembly with Emscripten and driven by a browser demo in `demos/`.

## Commands

- **Configure (once):** `emcmake cmake -S . -B build -D CMAKE_BUILD_TYPE=Debug` (or `Release` for `-O3`). Requires `EMSDK` env var set and `python` on PATH.
- **Build:** `./build.bat` (runs `cmake --build ./build -t clean` then `-t ephys`)
- **Run demo:** serve `demos/` with any static HTTP server and open `index.html` (wasm needs HTTP, not `file://`).
- No test suite or linter exists.

## Architecture

- `includes/ephys/*.h` + `src/*.cpp`: engine, all in namespace `ephys`. Two parallel engines:
  - Rigidbody: `rigidbody`, `collider`, `collision` (BVH broadphase), `contacts`, `forcegen`, `world`.
  - Particle (files prefixed `p`): `particle`, `pcontact(s)`, `pforcegen`, `plinks`, `pworld`.
- JS bindings are generated by Emscripten's WebIDL binder from `ephys.idl`; `ephys-headers.h` is force-included into the generated glue and holds typedefs (e.g. `ContactList`, `BVHCircleNode`) that the IDL refers to.
- Build output goes to `demos/js/ephys/ephys.{js,wasm}` (MODULARIZE, export name `ephys`); `demos/js/main.js` loads it and runs the demo scene with jQuery.

## Key Invariants

- Adding/renaming an engine class or method that JS uses requires updating all of: the header, `src/` file, `EPHYS_SOURCES` in `CMakeLists.txt` (for new .cpp files), `ephys-headers.h` (new headers/typedefs), and `ephys.idl`.
- IDL conventions are documented at the top of `ephys.idl` (`[Value]`, `[Ref]`, `[Const]`, `[Prefix="ephys::"]`, `[NoDelete]` for abstract classes).
- `demos/js/ephys/` is build output: don't hand-edit it. CI (`.github/workflows/build.yml`) rebuilds on every push and auto-commits `demos/**`; `pages.yml` then deploys `demos/` to GitHub Pages from `main`.
