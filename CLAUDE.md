# CLAUDE.md

ephys: a 2D rigidbody physics engine in C++ (modeled on cyclone physics), compiled to WebAssembly with Emscripten and driven by a browser demo in `web/`, plus a native SDL3 + Dear ImGui app in `desktop/` for fast local builds and debugging.

## Commands

- Builds use CMake presets (`CMakePresets.json`, Ninja). Each preset has its own dir, `build/<preset>/`. `cmake --workflow --preset <name>` configures if needed, then builds incrementally.
- **Web:** `cmake --workflow --preset web-debug` (or `web-release` for `-O3`). Requires the `EMSDK` env var (the preset loads Emscripten's toolchain file from it) and `python` on PATH. Output goes to `web/dist/`.
- **Run web demo:** build, then serve `web/dist/` with any static HTTP server and open `index.html` (wasm needs HTTP, not `file://`).
- **Desktop:** `cmake --workflow --preset desktop-debug` (or `desktop-release`). The first configure fetches SDL3 and ImGui via `FetchContent`.
- **Run desktop:** `build/desktop-debug/desktop/ephys_desktop.exe`. Space pauses, right arrow steps, `r` resets; left click selects, right drag pans, wheel zooms.
- No test suite or linter exists.

## Architecture

- `includes/ephys/*.h` + `src/*.cpp`: engine, all in namespace `ephys`. Two parallel engines:
  - Rigidbody: `rigidbody`, `collider`, `collision` (BVH broadphase), `contacts`, `forcegen`, `world`.
  - Particle (files prefixed `p`): `particle`, `pcontact(s)`, `pforcegen`, `plinks`, `pworld`.
- `web/`: the wasm build target (`web/CMakeLists.txt`, target `ephys`). `desktop/`: the native SDL3 + ImGui target (`ephys_desktop`). The root `CMakeLists.txt` defines `EPHYS_SOURCES` and adds exactly one frontend per build dir: `web/` when the toolchain is Emscripten, otherwise the native `ephys_core` lib plus `desktop/`.
- JS bindings are generated by Emscripten's WebIDL binder from `web/ephys.idl`; `web/ephys-headers.h` is force-included into the generated glue and holds typedefs (e.g. `ContactList`, `BVHCircleNode`) that the IDL refers to.
- Build output goes to `web/dist/js/ephys/ephys.{js,wasm}` (MODULARIZE, export name `ephys`); a post-build step then copies `web/css`, `web/img`, `web/js` and `web/index.html` into `web/dist/`. `web/js/main.js` loads the module and runs the demo scene with jQuery.

## Key Invariants

- Adding/renaming an engine class or method that JS uses requires updating all of: the header, `src/` file, `EPHYS_SOURCES` in the root `CMakeLists.txt` (for new .cpp files), `web/ephys-headers.h` (new headers/typedefs), and `web/ephys.idl`.
- IDL conventions are documented at the top of `web/ephys.idl` (`[Value]`, `[Ref]`, `[Const]`, `[Prefix="ephys::"]`, `[NoDelete]` for abstract classes).
- `web/dist/` is gitignored build output: edit the site sources in `web/`, never `web/dist/`. CI (`.github/workflows/pages.yml`) runs only on pushes to `main`: it builds, uploads `web/dist/` as a Pages artifact and deploys it. Nothing is committed back to the repo.
